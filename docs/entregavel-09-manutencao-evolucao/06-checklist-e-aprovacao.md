# 6. Revisão por pares, aprovação da manutenção e checklist

**Este documento não é uma ata de reunião realizada.** Serve para o grupo revisar e ratificar o Entregável 9 de maneira auditável.

## Checklist de revisão técnica

- [ ] CRs correspondem ao estado do código no commit referenciado.
- [ ] Nenhuma mudança proposta foi descrita como implementada.
- [ ] O grupo ratificou regras: orçamento zero, datas importadas e política de erro na gravação.
- [ ] Prioridade e impacto de cada CR foram debatidos.
- [ ] A escolha entre refatorar, modernizar e substituir foi justificada para o prazo e o produto.
- [ ] Os testes de regressão e os procedimentos de rollback foram aceitos.
- [ ] O código e os dados existentes foram preservados.
- [ ] O PR deste entregável passou pelo `ci-quality-gate` e teve revisão independente.

## Registro real da decisão do grupo — preencher após reunião

| Campo | Registro |
|---|---|
| Data e horário | **A preencher após ocorrência** |
| Participantes (usuários/nomes) | **A preencher** |
| Revisor/relator | **A preencher** |
| Alternativa aprovada | **A preencher** |
| CRs aprovadas e prioridade | **A preencher** |
| Dúvidas ou divergências | **A preencher** |
| Decisão / justificativa | **A preencher** |
| Responsáveis e prazos | **A preencher** |
| Link de ata, issue ou PR | **A preencher** |

**Não preencher com nomes/assinaturas inventados.** A aprovação de um PR pode comprovar revisão do arquivo, mas não substitui automaticamente uma reunião específica sobre a política de manutenção.
